# JD Reading Assistant

本地优先（Local-first）的沉浸式英语阅读辅助工具：划词翻译、生词本、基于上下文的间隔重复（SRS）复习。

- **纯前端，无后端**：所有数据存在浏览器 IndexedDB（Dexie.js）里
- **BYOK（Bring Your Own Key）**：AI 模式下用户自带大模型 API Key（豆包 / OpenAI / Gemini），浏览器直连服务商；也可以用免费的常规辞典模式
- **极简阅读体验**：Notion / Medium 风格单列排版，划词弹出悬浮气泡

## 快速开始

需要 Node.js 20+。

```bash
npm install
npm run dev       # 启动开发服务器，固定 http://localhost:5173 ，改代码自动热更新
```

其他命令：

```bash
npm run lint      # 代码检查（oxlint）
npm run build     # 打包生产版本到 dist/（发布时才需要）
npm run preview   # 本地预览打包结果
```

## 使用方法

> 应用内也有完整的使用说明：点击顶部导航「**帮助**」（`#/help`）。

1. 在正文里**双击单词**或**拖选词组 / 句子**，选区上方会弹出翻译气泡（上方空间不够时自动显示在下方）
   - 选区会**自动吸附到完整单词**：只选了半个词（`perspecti`）会扩展成 `perspectives`；两端多选的空格和标点会被去掉（`skill.` → `skill`）；只选中标点 / 空格时不弹气泡。撇号夹在字母中间时算单词的一部分（`it's`），连字符算边界（`well-chosen` 里可以单独选 `chosen`）
2. 点击气泡里的 **Mark 标记生词**，该词连同所在原句存入本地生词本，正文里所有出现处都会高亮
3. **单击已高亮的词 / 词组**直接弹出它的意思，不用重新划选；高亮的是词组（如 `a wealth of`）时，单击其中任意位置查的是整个词组。想只查词组里的某个词，**双击**那个词或拖选它（单击后约 0.25 秒确认不是双击才弹出）
4. 再次选中（或单击）已标记的词，按钮显示「已标记 ✓」，再点一次即可取消标记（有笔记时会先确认，笔记会一起删除）
5. 点击空白处、按 `Esc` 或缩放窗口关闭气泡

**在这里结束本次阅读（横线）**：按住鼠标左键，在正文上**横着来回划两下以上**（像涂掉一行字），会在最近的那一行下面画一条虚线，并问「在这里结束本次阅读？」。点「是」后变成实线，记下位置；下次打开这本书时自动翻到那一页、滚动到横线处。**在横线那一行上双击**取消横线（不查词）；其他地方双击照旧查词。每本书只有一条横线，新划的替换旧的。只拖一下（或拖过头再拉回来一次）仍然是普通划词。位置记的是「第几章、本章第几段、那一行从第几个字开始」，所以调整阅读宽度、换设备重新排版后横线仍在同一句话那里；存在文章元数据的 `bookmark` 字段里，会同步到其他设备（示例文章存在本机 `jdra.sampleBookmark`）。

**笔记**：气泡里点「📝 添加笔记」，写这个词在这里的意思、例句、联想等。还没标记的词，笔记在点 Mark 时和单词一起保存（**Mark 就是保存**，保存后笔记显示成「📝 我的笔记」）；已标记的词再次选中时显示已保存的笔记，点「编辑」修改（光标在末尾），改了内容后主按钮变成「保存」，点「取消」放弃修改。关闭气泡时如有未保存的修改，会自动保存一次。笔记存在生词记录的 `note` 字段里，会同步、会进备份；在词汇库里可以查看 / 编辑 / 搜索，复习卡片背面也会显示「📝 我的笔记」。手机上弹出键盘时，底部卡片会用 `visualViewport` 抬到键盘上方（未在真机验证）。

高亮颜色：🟨 暖黄 = 新词（还没复习过）；🟪 淡紫 = 已开始复习（学习中 / 复习 / 重新学习）。**记熟的词不再高亮**：FSRS 记忆稳定性 ≥ 30 天（`FAMILIAR_STABILITY_DAYS`，一路按「认识」大约第 4 次复习后）的词正文里不再高亮；之后复习按了「忘记」、稳定性掉下来，高亮自动恢复。这些词仍在生词本和每日复习里，词汇库里显示「已熟悉 · 不高亮」。
高亮只匹配完全相同的词（忽略大小写），不识别词形变化（标记 `atrophy` 不会高亮 `atrophies`）。

### 书架与导入

阅读页左上角「📚 书架 · 导入」按钮（`#/library`）；书架还是空的时候，示例文章末尾也有一张导入提示卡片：

- **粘贴文本**：段落之间空一行；`Chapter 1`、`Part Two` 这类标题开头的段落自动分章
- **上传 TXT**：自动把硬换行接回成段落、识别章节标题；Project Gutenberg 的 TXT 会自动去掉前后的版权声明；没有章节又很长的文本自动按 60 段分成若干部分
- **上传 EPUB**：支持 **EPUB 2 和 EPUB 3**（固定版式的图画书 / 漫画基本是图片，提取不到文字）。按 spine 阅读顺序提取各章正文（`<p>`、标题、列表，以及老式电子书用来排段落的最内层 `<div>`），跳过目录页和 `linear="no"` 的封面等辅助页，读取书名和作者；**受 DRM 保护的 EPUB 会提示无法导入**。Kindle 的 AZW / KFX / MOBI 不是 EPUB 格式，也不支持
- **上传 PDF**（上限 200 MB）：用 pdf.js 提取文字，再根据每行的位置、字号和字体还原段落（`src/services/pdfLayout.js`）：段落间距、粗体 / 大字号小标题、项目符号和编号列表、行末连字符断词、跨页段落、每页重复的页眉页脚和页码、两栏表格（输出为「左栏：右栏」）、双栏正文（先左栏后右栏）。分章优先用 PDF 自带的书签目录，没有书签时识别 `Chapter N` 这类标题。元数据里无意义的书名（`about:blank`、`Untitled` 等）改用文件名。**扫描版 PDF**（内容是图片）会提示暂不支持；**有密码的 PDF** 无法导入
- **保存原始文件**：PDF 和 EPUB 的原始文件也会保存（本机 + 同步到 Drive），用于：
  - **EPUB 插图**：正文里记着图片在 EPUB 包里的路径，阅读时从原始 EPUB 里取出来，显示在原来的位置；只取当前页用到的图片，翻页 / 离开时释放（`src/hooks/useEpubImages.js`）
  - **PDF「📄 原版页面」**：阅读页右上角的按钮，用 pdf.js 把当前这页正文对应的原 PDF 页面按原样画出来（图片、图表、原始排版），可前后翻页；关闭时销毁 pdf.js 文档、释放内存（`src/components/PdfViewer.jsx`）。每段文字都记了它在原 PDF 里的页码，所以能定位到对应的页
- 默认用「重新排版的文字」阅读（适配手机屏幕、可以划词 / 高亮 / 复习），原版页面按需查看
- **阅读宽度可调**：阅读页右上角「窄 / 标准 / 宽」（672 / 768 / 896 px，默认标准），保存在本机设置里（`readerWidth`，不同步）；手机上不显示，正文总是占满屏幕
- **自动分层次显示**（`src/utils/paragraphStyle.js`）：导入时原书的层次（尤其 PDF）被压平成了普通段落，阅读时再按规则识别回来，用不同样式显示，已导入的书无需重新导入：
  - 小标题（短、没有句末标点、大写字母开头）：无衬线粗体，上方多留空白
  - 「小标题：内容」（PDF 表格行）：冒号前加粗
  - 编号列表（`1. …`）/ 圆点列表（`- …`）：缩进，编号 / 圆点挂在左边，开头的「小标题:」加粗
  - 问答：`1.Question …` 整句加粗、左侧竖线；`Answer:` 加粗
  - 显示出来的文字和原文一字不差（只加粗 / 缩进其中一部分），所以划词、原句提取、高亮不受影响；规则判断偶尔会误判，比如一句很短又没有句号的正文可能被当成小标题
- 多章节时右上角可选章节；**长章节自动分页**（按段落边界切分，每页约 1800 词，`src/services/paginate.js` 的 `WORDS_PER_PAGE`），底部「上一页 / 第 x / n 页 / 下一页」，翻到章节边界时自动跨到上一章最后一页 / 下一章第一页；电脑上可用 ← → 键翻页
- 每本书记住读到的章节、页码和页内滚动位置；旧版只记了整章滚动位置的进度会自动换算成页码
- 分页只在显示时计算，不存数据库；高亮只处理当前页，长章节也不会卡
- 文件只在浏览器里解析，不经过任何服务器；EPUB 解析用 JSZip、PDF 用 pdf.js，都是导入时才按需加载
- 暂不支持导入网页链接（浏览器不能跨域抓取其他网站，需要后端代理），可以复制正文后粘贴

### 词汇库

顶部导航「**词汇库**」（`#/vocab`，手机上显示「词汇」），或 ⚙️ 菜单里的「生词本 · N 个」：

- 搜索（单词 / 释义 / 原句）、按状态筛选（新词 / 学习中 / 复习 / 已到期 / 缺释义 / 疑似残缺）、排序（最近添加 / 字母 / 下次复习）
- 展开查看完整释义、词根、原句（单词高亮）、出处、复习 / 遗忘次数；可以**删除**（软删除，会同步）或**重新查询释义**（只更新释义字段，不影响复习进度）
- **疑似残缺**：原句里找不到这个完整单词，但能找到它作为某个单词的一部分（例如早期选中半个词存成的 `perspecti`），建议删除后重新标记
- 列表里显示笔记的第一行；展开后可以编辑笔记；搜索也会搜笔记；筛选里有「有笔记」「已熟悉」
- **批量补全释义**：对没有释义或还是 `Mock Translation` 的词，用当前查词模式逐个重新查询（每个词之间停 0.3 秒，可随时停止）；AI 模式下确认框会提示按用量计费

### 在 iPhone / iPad 上使用

- **点按单词**直接查词；**点按高亮**查整个高亮词组（想查词组里的单个词，长按选中它）；**长按拖动**选词组 / 句子，停手约 0.4 秒后弹出。触屏上释义从**底部弹出卡片**（避开 iOS 自带的「拷贝 / 查询」菜单），单词被卡片挡住时页面自动上滚
- **手指横着来回划两下以上**：在那一行下面画「结束阅读」横线；**双击横线那一行**取消
- 每日复习：点卡片任意位置翻面；触屏设备上不显示键盘快捷键提示
- 支持「**添加到主屏幕**」（PWA）：Safari → 分享 → 添加到主屏幕，之后全屏打开
- iOS 上 **Safari 和主屏幕 App 的数据互相独立**，建议固定从主屏幕图标打开；设备之间用 Google Drive 同步（见下文）

### 查词模式

点击顶部导航「**模式**」切换（旁边小标签显示当前模式）：

| 模式 | 释义来源 | 说明 |
|---|---|---|
| **常规辞典**（默认） | 单词 / 词组：内置 [ECDICT](https://github.com/skywind3000/ECDICT) 英汉词典；词典里没有的词和整句：MyMemory 机器翻译 | 免费，无需配置。词典离线可用、能识别变形词（`atrophies` → `atrophy`），每行一个词性的释义；不结合上下文。MyMemory 匿名每天约 5000 字符额度 |
| **AI Agent** | 豆包 / OpenAI / Gemini | 选中内容 + 所在原句一起发给模型，返回贴合语境的释义、词性、音标、词根（严格 JSON）。需要自己的 API Key |

AI Agent 设置：选服务商 → 填 API Key 和模型 → 「测试连接」。设置自动保存在 localStorage（`jdra.settings`），每家服务商的 Key / 模型分开存。默认模型：OpenAI `gpt-4o-mini`、Gemini `gemini-2.5-flash`；豆包没有默认值，需要填火山方舟的模型 ID 或接入点 ID（`ep-…`）。

划词气泡：查询中显示骨架屏（此时 Mark 按钮不可用），出错时显示原因，底部显示释义来源（辞典 / 豆包 / OpenAI / Gemini）。同一模式下重复查同一个词会命中内存缓存，不重复请求。

### 每日复习

点击顶部导航「**每日复习**」（或访问 `#/review`），黑色角标是当前到期待复习的词数（每 30 秒自动刷新）。

1. **正面**：英文单词 + 它所在的原句（单词在句中高亮），借助语境**回想中文意思**（英译中，练的是阅读理解）。标记的是整句时，正面就是这句英文
2. 按 **空格**（或点「显示答案」）翻开：中文释义、词性、词根（如果有）、出处
3. 按自己的记忆程度评分，每个按钮下面会显示「选它的话，下次多久后复习」：

| 按钮 | 快捷键 | FSRS 评分 | 新词时的下次复习 |
|---|---|---|---|
| 忘记 | `1` | Again | 1 分钟 |
| 模糊 | `2` | Hard | 6 分钟 |
| 认识 | `3` | Good | 10 分钟 |

- 评分后下次到期在 **20 分钟内**（学习阶段的短间隔），这张卡会排到队尾，**本轮再出现一次**；否则本轮完成。所以新词一般要连续「认识」两次，才会进入以「天」为单位的长期复习
- 每次评分都立即写回 IndexedDB，中途离开不会丢进度
- 本轮的复习队列在进入页面时生成，复习过程中新到期的词，下次进入时才会出现

### Google Drive 同步

导航栏右上角的**云朵图标**（或 ⚙️）→「连接 Google Drive」。云朵图标显示同步状态：灰色 = 未连接，绿色带勾 = 已同步，橙色带感叹号 = 授权过期或出错。每个用户用**自己的 Google 账号**授权，数据存到**他自己 Drive 的应用隐藏文件夹**（`appDataFolder`；在 Drive 里看不到，只有本应用能读写）。网站不经手任何人的数据，请求从浏览器直接发给 Google。

Drive 上的文件布局（`src/sync/google.js`）：

| 文件 | 内容 | 什么时候读写 |
|---|---|---|
| `jd-reading-sync.json` | 索引：全部生词（含复习进度、删除记录）+ 书架目录（每本书的元数据、阅读进度） | 每次同步，体积很小 |
| `article-<id>.json` | 某本书的正文（章节和段落） | 导入后上传一次；**打开这本书时才下载** |
| `original-<id>` | 某本书的原始文件（PDF / EPUB） | 导入后上传一次；查看原版页面 / 显示插图时才下载 |

- **按需下载 + 本机缓存**：新设备连接后只下载索引，书架上的书显示「☁️ 云端」；打开哪本才下载哪本的正文（`ensureContent`），原始文件同理（`ensureOriginal`）。本机只缓存**最近打开的 3 本书**（`CACHE_BOOKS`），更早的自动清掉，再打开时重新下载；**还没上传到 Drive 的书永远不会被清理**（它是唯一一份）
- **上传**：书的正文和原始文件导入后只上传一次（之后内容不变）；超过 4 MB 的文件用 Drive 的分段上传（resumable），读不到 `Location` 响应头时用 `X-GUploader-UploadID` 拼出会话地址
- **删除**：在书架上删掉一本书后，下次同步会删除 Drive 上它的正文和原始文件，释放用户的 Drive 空间
- **兼容旧版**：旧版同步文件把正文放在索引里；新版第一次同步时会自动拆成单独的文件，并把索引改写为 v2

- **授权**：Google Identity Services 的 token 模式（纯前端），权限只有 `drive.appdata`。access token 约 1 小时过期，存在 localStorage（`jdra.googleToken`）；过期后 ⚙️ 上出现小圆点，点「重新连接」
- **何时同步**：打开应用时、本地数据变化后 3 秒（连续操作合并为一次）、切回页面时（距上次 30 秒以上）、手动「立即同步」
- **合并规则**（`src/sync/merge.js`，备份导入也用这套）：逐条合并，生词按小写单词匹配、文章按 id 匹配；两边都有时 `updatedAt` 更新的那份胜出；删除是软删除（`deletedAt`），删除记录也会同步
- **不同步**：API Key、查词模式等设置（每台设备单独设置）
- 「断开」会撤销授权，本机和 Drive 上的数据都保留
- 「**查看云端数据**」：读取 Drive 上的索引，显示云端 / 本机各自的生词数、文章数、云端更新时间、索引大小，以及书的正文 / 原始文件的数量和总大小（只统计，不下载），提示两边是否一致；可以下载云端的索引文件。同步文件在 Google Drive 网页上看不到（应用隐藏文件夹），只能在 Drive 设置 →「管理应用」里看到这个应用占用的隐藏数据大小
- Google Cloud 项目目前是**测试模式**：只有在 Google Cloud 后台「测试用户」名单里的账号能授权（最多 100 个）。要开放给所有人，需要发布应用并完成基础验证（隐私政策、首页、域名验证）
- OAuth Client ID 写在 `src/sync/google.js`（Client ID 是公开信息）；已授权的 JavaScript 来源：线上域名和 `http://localhost:5173`

### 手动备份（JSON）

点击右上角 ⚙️：

- **导出备份**：下载 `jd-reading-words-YYYY-MM-DD.json`，包含全部生词（含复习进度）、书架目录，以及**本机缓存着的书的正文**。原始 PDF / EPUB 文件太大，不放进备份（连接 Google Drive 时它们已经在云端）
- **从备份导入**：按和 Drive 同步相同的规则逐条合并（较新的胜出），文件里缺失的字段自动补默认值；兼容旧版的备份文件（v1 只有生词，v2 的正文在文章记录里）

**备份提醒**（只在没连接 Google Drive 时显示）：有未备份的生词，并且满足下面任一条件时，⚙️ 右上角会出现橙色小圆点，菜单里也会显示「有 N 个生词还没备份」：

- 距离上次备份已满 **7 天**（从未备份过时，从最早那个生词的创建时间算起）
- 未备份的生词达到 **20 个**

「未备份的生词」指上次备份之后新加的词。导出后提醒立即消失。导入备份时，也会把备份文件的导出时间记为"上次备份"，所以在新浏览器里恢复备份后不会马上被提醒。上次备份时间存在 localStorage（`jdra.lastBackupAt`）。阈值可在 `src/db/backupReminder.js` 里修改。

### 数据存在哪？会丢吗？

日常数据存在浏览器 IndexedDB 中，刷新、重启 dev server、关闭浏览器、重启电脑都**不会丢**。IndexedDB 存在磁盘上、异步读写，几千上万个生词也只有几 MB，不会影响浏览器性能。

以下情况会丢失或"看不到"，建议连接 Google Drive 同步，或定期导出备份：

- 清除浏览器数据 / 站点数据、使用无痕模式
- 换浏览器（每个浏览器各存各的）
- **端口变了**：数据按「域名 + 端口」隔离，`localhost:5173` 和 `localhost:5174` 是两个独立的数据库。为此 `vite.config.js` 已把开发端口固定为 **5173**（`strictPort`）：端口被占用时 `npm run dev` 会直接报错，而不是悄悄换端口。遇到报错先关掉占用 5173 的旧进程（通常是另一个没关的 dev server）
- Safari 会清理 7 天未访问网站的存储

纯静态网站，可以免费部署到 Vercel：用 GitHub 账号登录 [vercel.com](https://vercel.com) → Add New Project → 导入 `jd-reading-assistant` 仓库 → Deploy。Vercel 会自动识别 Vite（构建命令 `npm run build`，输出目录 `dist`），无需任何配置；页面切换用 hash 路由（`#/review`），不需要配置重写规则。之后每次推送到 GitHub 都会自动重新部署。

## 数据结构

IndexedDB 数据库 `jd-reading-assistant`（Dexie schema v3），四张表：

| 表 | 内容 | 同步 | 索引 |
|---|---|---|---|
| `words` | 生词 | ✅ 索引文件 | `id, word, due, state, createdAt, updatedAt` |
| `articles` | 书的元数据（不含正文） | ✅ 索引文件 | `id, updatedAt` |
| `contents` | 书的正文，本机缓存（最近 3 本） | 单独文件，按需下载 | `id, lastOpenedAt, uploaded` |
| `originals` | 原始 PDF / EPUB 的 Blob，本机缓存 | 单独文件，按需下载 | `id, lastOpenedAt, uploaded` |

`uploaded`（0 / 1）表示是否已经上传到 Drive，只有已上传的才会被缓存清理；建索引是为了清理缓存时只读主键，不必把整本书读进内存。

生词 `words`：

```js
{
  id: "uuid",
  word: "ubiquitous",
  translation: "无处不在的",
  context: "Smartphones have become ubiquitous in our daily lives, ...", // 所在原句
  phonetic: "/juːˈbɪk.wə.təs/",  // 音标（查词时拿到才有）
  pos: "adj.",
  etymology: null,
  source: "The Quiet Power of Deep Reading",  // 文章标题
  note: "这里指“随处可见”",            // 用户自己写的笔记（可为空），会同步
  createdAt: "2026-11-19T07:03:09.281Z",

  // ts-fsrs 调度参数（设计文档定义的 5 个）
  due: "2026-11-19T07:03:09.281Z",  // 下次到期时间；新词保存即到期
  state: 0,        // 0 New, 1 Learning, 2 Review, 3 Relearning
  repetition: 0,   // 复习次数（对应 FSRS 的 reps）
  stability: 0,
  difficulty: 0,

  // 阶段三补充：FSRS 准确调度还需要的字段（设计文档外新增）
  lapses: 0,          // 遗忘次数
  lastReview: null,   // 上次复习时间
  learningSteps: 0,   // 当前处于第几个学习步骤
  scheduledDays: 0,
  elapsedDays: 0,

  // v2：多设备同步
  updatedAt: "2026-11-19T07:03:09.281Z", // 最后修改时间（标记、复习、删除都会更新），同步时较新的胜出
  deletedAt: null,                        // 取消标记时设为删除时间（软删除），所有查询都会过滤掉
}
```

文章元数据 `articles`：

```js
{
  id: "uuid",
  title: "The Little Test Book",
  author: "Jane Author",            // EPUB / PDF 才有
  kind: "pdf",                      // paste / txt / epub / pdf
  chapterCount: 3, wordCount: 1122, contentSize: 7439,          // 书架显示用
  hasOriginal: true, originalName: "book.pdf", originalType: "application/pdf", originalSize: 64050,
  progress: { chapter: 1, page: 2, ratio: 0.42 }, // 读到第几章、第几页（都从 0 开始）、页内滚动位置
  createdAt, updatedAt, deletedAt,
}
```

正文 `contents`（Drive 上的 `article-<id>.json` 同结构）：

```js
{
  id: "uuid",
  chapters: [{
    title: "Chapter One",
    paragraphs: ["文字段落", { type: "img", src: "OEBPS/images/fig1.png", alt: "..." }], // EPUB 插图记成对象
    pages: [0, 0, 1],               // 仅 PDF：每段在原 PDF 里的页码（从 0 开始），用于「原版页面」
  }],
  lastOpenedAt, uploaded,           // 本机缓存信息，不上传
}
```

内置示例文章不存数据库（id 为 `sample`），不参与同步。当前打开的文章存在 localStorage（`jdra.currentArticle`），每台设备各自记。

阶段三之前创建的旧记录没有这 5 个补充字段，读取时会自动补默认值，可以正常复习。v1 数据库升级到 v2 时，会给旧记录补上 `updatedAt`（取上次复习时间或创建时间）和 `deletedAt: null`。v2 升级到 v3 时，文章记录上的 `chapters` 搬到 `contents` 表，文章记录只留元数据。

同一个词忽略大小写去重。调试时可在浏览器 DevTools → Application → IndexedDB 中查看 / 删除数据。

备份文件格式：

```js
{
  "app": "jd-reading-assistant",
  "version": 3,                       // v1 只有 words；v2 的正文在 articles[].chapters 里
  "exportedAt": "2026-11-18T23:10:00.000Z",
  "count": 2,
  "words": [ /* 生词记录（不含已删除的） */ ],
  "articles": [ /* 文章元数据 */ ],
  "contents": [ /* 本机缓存着的书的正文 { id, chapters } */ ]
}
```

导入时也接受直接是生词数组的 JSON。

## 已知限制

- mark.js 会直接修改 DOM；切换文章 / 章节时用 key 让整个 `<article>` 重新挂载，避免和 React 冲突
- 不连接 Google Drive 时只能手动导出备份（纯前端无法在后台写本地文件），只能靠提醒
- Google Drive 同步只用模拟的 Google 接口测过（两台设备合并、按需下载、缓存清理、删除同步、授权过期、401），还没用真实 Google 账号验证；**真实 Drive 的分段上传（4 MB 以上的原始文件）是否能拿到上传会话地址**、iPhone 主屏幕 App 里 Google 授权弹窗能否正常工作，都需要实测
- 同步是“最后修改的胜出”：同一个词在两台设备上离线各复习了一次，只会保留后同步的那次
- 没连接 Google Drive 时，书只存在本机，不会被缓存清理；被清理过的书在断开 Drive 后无法打开（会提示连接 Drive）
- PDF：扫描版（图片）不支持；双栏、复杂排版的还原效果不保证；在 iPhone / iPad 上导入几十 MB 的 PDF 可能很慢或内存不足，需要真机测试；有密码的 PDF 的提示没有实测
- 生词出处只记录文章标题，删除文章后生词仍保留
- 备份提醒只统计"新增"的词；取消标记（删除）不算作需要备份的变更
- 高亮不识别词形变化；生词很多时，每次增删都要重新全文匹配一遍，是潜在的性能瓶颈
- 常规辞典不结合上下文，会列出所有词性的释义，需要自己判断是哪个意思（例如 `atrophies` 在原句里是动词，ECDICT 只收了名词义）
- 内置词典只有 5.8 万常用词；之外的词走 MyMemory，它的单词翻译来自网友提交的翻译记忆，质量不稳定（已过滤掉整句、乱码等明显错误的候选），气泡里会标注「机器翻译」；MyMemory 免费额度用完后当天无法翻译
- 豆包（火山方舟）出错时的响应不带跨域头，浏览器读不到错误详情，只能提示「无法读取豆包的返回」
- AI 模式的默认模型名（`gpt-4o-mini`、`gemini-2.5-flash`）没有用真实 Key 验证过，服务商下线模型后需要手动改
- API Key 明文存在 localStorage，页面里任何脚本都能读到。个人本地使用风险低；公开部署时请用设置了额度上限的 Key
- 早期标记的词释义是演示用的「Mock Translation」：在词汇库里用「补全释义」批量重新查询即可
- iPhone / iPad 适配只在 Chrome 的设备模拟里测过，还没在真机 Safari 上验证（长按选词、iOS 菜单与卡片的配合、导出 / 导入文件）
- 还没有 Service Worker：添加到主屏幕后仍需联网才能打开（内置词典加载过一次后由浏览器缓存）
